# Rusclimate (Hommyn) для Home Assistant

[![Открыть репозиторий в HACS.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=he110&repository=ha-rusclimate&category=integration)
[![Добавить интеграцию Rusclimate.](https://my.home-assistant.io/badges/config_flow_start.svg)](https://my.home-assistant.io/redirect/config_flow_start/?domain=rusclimate)

Интеграция управляет устройствами Русклимат из приложения **Hommyn** (Ballu, Electrolux и другие)
напрямую из Home Assistant. Работает **через локальную сеть**, **через облако производителя**
или через оба канала с автоматическим переключением.

Сейчас поддерживается бризер **Ballu ONEAIR ASP-100 / Electrolux EASP-100** (тип устройства 69 в Hommyn).

[English version](README.md)

## Возможности

- **Два канала к одному устройству.**
  - Локальный UDP: тот же зашифрованный протокол, которым приложение пользуется в домашнем Wi-Fi.
  - MQTT-облако производителя.
  - Изменения по обоим каналам приходят за доли секунды.
- **Режим подключения задаётся для каждого устройства:**
  - **Авто** (по умолчанию). Сначала используется локальная сеть. Если локальная сессия оборвалась,
    команды и состояние сразу идут через облако, а когда локальный канал восстановится, интеграция
    вернётся на него. Если устройство не подтвердило команду за 3 секунды, она один раз повторяется
    через другой канал.
  - **Только локально.** Облако не используется, интернет не нужен.
  - **Только облако.** Подходит для устройств в другой сети.
- Приложение Hommyn продолжает работать параллельно с Home Assistant.
- Устройства в сети находятся автоматически.
- Если устройство 30 минут недоступно по локальной сети, в **Настройки → Ремонт** появится
  предупреждение. Оно исчезнет само, когда связь восстановится.

## Сущности (ASP-100)

| Сущность | Что делает |
|---|---|
| Climate | Вкл/выкл, пресеты (ручной, ночной, турбо, проветривание; «авто» — только с датчиком CO₂), скорость 1–7, уставка подогрева 5–25 °C. Включение восстанавливает последний режим, как в приложении. |
| Температура приточного воздуха | Температура воздуха после нагревателя |
| CO₂ | Доступна, только если установлен датчик (опция) |
| Фильтр | Остаток ресурса фильтра, % |
| Окончание турбо | Время, когда закончится 15-минутный турбо-режим |
| Звук | Встроенные звуки: дождь, море, лес, птицы, костёр |
| Звук кнопок, Автоотключение подсветки | Настройки устройства |
| Проблема | Включается, когда устройство сообщает код ошибки |
| Подключение | Через какой канал сейчас работает устройство: локально, облако или нет связи (диагностика) |
| Уровень сигнала | RSSI Wi-Fi (диагностика, по умолчанию выключен) |

## Требования

- Home Assistant 2026.9 или новее.
- Для локального канала Home Assistant и устройство должны быть в одном сегменте сети:
  mDNS-анонсы устройства должны доходить до HA.

## Установка

HACS → ⋮ → Custom repositories → добавить этот репозиторий как *Integration* → установить
**Rusclimate (Hommyn)** → перезапустить Home Assistant.

## Настройка

1. В Hommyn откройте устройство → **Настройки → Контроль прав → Поделиться** и под QR-кодом нажмите
   **Поделиться**. Скопируйте ссылку вида `rusklimat://device-share/rusclimate/69/<mac>?token=…`.
2. В Home Assistant откройте **Настройки → Устройства и службы**. Найденное устройство появится там сразу:
   нажмите **Добавить** и вставьте ссылку. Можно и вручную: **Добавить интеграцию → Rusclimate (Hommyn)**.
3. Выберите режим подключения.

На каждое устройство нужна своя ссылка. Комната из ссылки станет предлагаемой зоной устройства.

## Настройки

**Настроить** в записи интеграции меняет режим подключения. **Перенастроить** принимает новую ссылку
для того же устройства, например после его повторного добавления в приложении.

## Пример

```yaml
automation:
  - alias: "Бризер: ночной режим в 23:00"
    triggers:
      - trigger: time
        at: "23:00:00"
    actions:
      - action: climate.set_preset_mode
        target:
          entity_id: climate.spalnia_brizer
        data:
          preset_mode: night
```

## Безопасность

- **Ссылка «Поделиться» — это пароль.** По одному её токену любой может управлять устройством через
  облако. Home Assistant хранит ссылку в записи интеграции, в диагностике она скрыта.
- Облачный канал входит так же, как приложение: со встроенными в Hommyn учётными данными (они
  одинаковы у всех пользователей) и уникальным идентификатором клиента. Локальному каналу интернет не нужен.
- Команды никогда не отправляются retained-сообщениями MQTT.

## Если что-то не так

- **В режиме «Авто» подключение показывает «Облако».** Значит, HA не видит mDNS-анонсы устройства
  (`_syncleo._udp`). Проверьте, что HA и устройство в одном сегменте сети и мультикаст не фильтруется.
- **В режиме «Только облако» устройство недоступно после перезапуска HA.** Брокер производителя
  у части устройств хранит устаревший флаг «офлайн», пока устройство не пришлёт свежее обновление.
  Измените что-нибудь на устройстве или используйте режим «Авто».
- Для отчёта об ошибке скачайте диагностику со страницы устройства.

## Ограничения

- Ночной режим всегда работает на скорости 1, как и в приложении Hommyn: отдельной настройки ночной
  скорости у устройства нет (проверено на ASP-100, прошивка модуля 1.38). Любая смена скорости
  выводит из ночного режима.

## Как это работает

Устройство объявляет себя по mDNS. UDP-порт и ключ X25519 меняются после каждой перезагрузки, поэтому
интеграция следит за анонсами и переподключается.

Состояние присылают оба канала:
- локальная сессия (X25519 + AES-CBC, на базе [pysyncleo](https://github.com/DeKaN/pysyncleo));
- облачная MQTT-сессия.

В режиме «Авто» источник правды — активный канал. Второй канал дополняет только то, чего активный
не сообщает (например, задержки Wi-Fi из облака).
